# 采集与简体中文 OCR：统一测试指南

## 本轮交付

扫描后自动打开“调整四角”，Vision 建议页面边缘，用户可拖动左上、右上、右下、左下四角，也可恢复整页。自动检测失败不会挡住手动校正。每次点“使用此校正”生成一份独立 JPEG；只有确认保存后才写入资料库，原件字节、校验值和路径保持独立。

阅读页可重新调整四角，并再次追加版本。OCR 在保存后使用最新校正图（无校正图时使用原件）。每条结果记录文本、识别框、语言、模型修订、置信度、耗时与源资产；识别框采用朝向修正后的左上原点、0...1 坐标。阅读器仅在展示同一源资产时允许叠加框，不将校正图的框直接放到原件上。

人工标签在扫描时和“文字与标签”中可添加，中文或英文逗号分隔。OCR 空白、失败或系统不支持简体中文时，原件和标签仍可保存、重启恢复、检索。

## iPhone 一次性测试

1. 飞行模式下创建手账，拍摄一页手写中文。确认出现自动选区；拖动四角修正，检查贴在页边的票根没有被裁掉。
2. 点“使用此校正”，再点“保存并识别中文”。从列表打开，切换原件/校正图。原件应完整、校正图应为正视裁边结果。
3. 点击“显示识别框”，确认框贴合实际文字。切换到原件后，不应显示校正图的错误位置框。
4. 进入“文字与标签”：对照识别文本、置信度和框；手动添加“旅行”等标签并保存。返回页面列表，以识别文字或标签搜索。
5. 用空白页、极淡字迹或复杂剪贴页重复一次，检查识别失败/无文字时仍能按人工标签找到页面。
6. 从阅读页重新调整四角，检查生成新的校正资产，并重新识别；关闭应用再打开，确认最新图片、识别文本和标签仍在。
7. 导入一张带 EXIF 旋转信息的相册图片，检查四角、校正方向和 OCR 框没有旋转或镜像。

## 真实手写样本验证

目前没有真实手写样本，因此本轮不能声称手写识别准确率已达标。自动化测试中的中文是生成的印刷夹具，用于验证 Vision API、方向、坐标和存储链路；真实字迹必须另测。

建议用至少 30 页自有样本，覆盖清楚手写、连笔、淡墨、方格背景、贴纸遮挡、混合英文数字与竖排。首版只要求简体中文，不承诺繁体/竖排/艺术字体效果。保留失败页的人工标签回退。

可以在 iPhone 的“文字与标签 → 手写样本验证”中抄录正确文本并查看单页字符错误率。长篇或多页可在 Mac 批量运行：

```sh
mkdir -p Samples Reports
# 把自有照片放进 Samples；复制并编辑 docs/ocr-samples.example.json 为 Samples/samples.json。
swift run --package-path InkArchiveCore InkArchiveValidate \
  Samples/samples.json Reports/ocr-report-01.json
```

示例清单中的 `image` 相对于清单目录。每项提供匿名 ID、文件名和准确抄录的 reference；可选 `quad` 指定四角，坐标结构与 DocumentQuad 一致。未提供 quad 时评价整张原件。使用四角裁切时，reference 必须对应裁切区域。

报告保存模型修订、系统版本、图片校验值、原始识别结果、置信度、识别框、耗时、字符错误率与失败原因。字符错误率仅移除空白，标点、漏字、多字和错字均计入；插入很多多余字符时可超过 100%，不是置信度。汇总按成功样本的参考字符总数加权，错误样本单独列出，不当作零错误。

真实图片与报告默认放在已忽略的 Samples/、Reports/ 目录，留在本地；此工具没有上传逻辑。它不覆盖已有报告文件，请每次换一个报告名称。

## 已知边界

自动检测可能把页内照片或大剪贴物误认为页面，用户需要手动确认。四角校正处理平面透视，不修复装订处弯曲。JPEG 校正结果最长边限制为 6000 像素，显示预览更小，原件分辨率不变。中文 OCR 仍可能识别出混排的数字/英文，但不提供单独的非中文模型配置。
